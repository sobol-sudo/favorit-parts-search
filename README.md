# Подбор автозапчастей

Клиентское приложение на React для поиска автозапчастей и аналогов через API «Проценка» ([документация](https://lk.favorit-parts.ru/static/wsprice.pdf)).

## Как работает

1. **Поиск производителей.** Вводим артикул — после паузы в наборе (500 мс, от 3 символов) уходит запрос к API, показываем список брендов, выпускающих деталь с таким номером, и общий остаток. Сначала бренды в наличии. После выбора список сворачивается до выбранного бренда (кнопка «Сменить производителя»), чтобы не листать до результатов.
2. **Аналоги и предложения.** Выбираем производителя — повторный запрос с номером, брендом и `analogues=on`.
   - **Искомая деталь** — отдельной карточкой: цена «от», общий остаток и предложения по складам строкой «склад · срок · остаток · цена».
   - **Аналоги других производителей** — таблица: производитель, номер, название, цена, остаток, срок отгрузки. Одна строка — одна позиция; по клику раскрывается разбивка по складам. Сначала позиции в наличии, внутри — по возрастанию цены.
   - Цена — минимальная среди складов с остатком (поле `price` товара API просит не использовать). Срок показан в днях («завтра», «через 3 дн.»), точная дата — в подсказке.

   У популярных артикулов аналогов сотни, а складов — тысячи (например, MEYLE 7160500039S: 741 аналог и ~6400 складских предложений), поэтому по умолчанию включён фильтр «Только в наличии», а список выводится порциями по 50 с кнопкой «Показать ещё».

## Стек

- React 19, Vite
- Redux Toolkit (`createSlice`, `createAsyncThunk`, `createSelector`), react-redux
- Bootstrap 5
- JavaScript, без TypeScript — по условию задания

## Состояния и ошибки

- Лоадеры на обоих шагах.
- «Ничего не найдено» — API в этом случае возвращает массив с одной пустой записью, такие записи отфильтровываются.
- Ошибки показываются понятным текстом без кодов, с кнопкой «Повторить»: нет интернета, долгий ответ (таймаут 15 с), превышен лимит запросов, сервис недоступен. Технические подробности (HTTP-статус, ответ API) пишутся в консоль.
- API возвращает ошибку лимита (`Request quota exceeded!`, HTTP 403) для части грузового ассортимента — на демо-ключе это воспроизводится, например, на артикуле 716 / Hans.
- Устаревшие запросы отменяются (`AbortController` через `thunk.abort()`), а ответ по ранее выбранному бренду не перетирает актуальный.
- Enter и автопоиск не отправляют один и тот же запрос дважды.

## Адаптивность

На узких экранах номер и название переносятся под производителя, второстепенные колонки скрываются — таблица помещается в экран без горизонтальной прокрутки. После выбора бренда страница плавно прокручивается к результатам.

## Запуск

```bash
npm install
npm run dev
```

Ключ покупателя задаётся в `.env` (см. `.env.example`), по умолчанию — демо-ключ из документации.

## Почему запросы идут через прокси

API доступно только по HTTP, а страница на HTTPS не может обращаться к HTTP-ресурсам (mixed content). Поэтому фронтенд ходит на `/api/hsprice`:

- локально запрос проксирует dev-сервер Vite (`vite.config.js`);
- на Vercel — rewrite в `vercel.json`.

